# Internationalization (i18n)

Animae separates **four locale settings** (all BCP-47 tags, configured independently):

| Setting | Config / API | Purpose |
|---|---|---|
| **UI locale** | `i18n.locale`, `createEngine({ i18n: { locale } })`, CLI `--lang`, env `ANIMAE_LOCALE`, web client `hello.locale` / `set_locale` | **Display strings** for humans: errors, CLI/TUI/web chrome, action labels, panel titles, achievement names, `$t:` string tables resolved at presentation time |
| **Prompt locale** | `i18n.promptLocale` | Language of **static LLM prompt scaffolding** under `engine/src/prompts/<locale>/` (appraisal, render, safety, memory, etc.) |
| **Output locale** | `i18n.outputLocale` (defaults to UI locale) | Language the model must use for **player-facing** narration/dialogue; injected via catalog message + `Intl.DisplayNames`. Takes precedence over `card.identity.language` and `world.language` unless a turn passes an explicit per-turn override. |
| **Content locale** | `i18n.contentLocale` (defaults to **`promptLocale`**, not output locale) | **LLM-facing authored content** loaded from `locales/<locale>/` overlay trees (persona bodies, knowledge, templates, scene briefs, card text fed into prompts) |

Explicit `i18n.contentLocale` in config still wins over the prompt-locale default.

When `contentLocale` is not the prompt locale (e.g. an English LLM layer), the **content overlay chain** falls back through `promptLocale` after the requested tag so missing `locales/en/**` files still load `locales/zh-CN/**` mirrors.

## Two content lanes

1. **LLM-facing content** — resolved from locale overlay trees `<root>/locales/<locale>/**` using **`contentLocale`** (default `promptLocale`). The model is instructed (via `outputLocale`) to write player-visible text in the UI/output language.
2. **Display strings** — resolved from string tables (`strings/<locale>.yaml`, `locales/<locale>/strings.yaml`, or package catalogs) using **`uiLocale`** per viewer (per WebSocket client on the server). Authored YAML may use `$t:key`; loaders lift these to `{ i18n: { key } }` for **late binding** so replay, rewind, and mid-session language switches do not rewrite the timeline.

### Late binding in engine state and wire payloads

- Timeline events and `EngineState` may carry `{ $t: key, params? }` or `{ i18n: { key, params? } }` instead of final copy.
- UIs call `localize(value, locale)` / `localizeDeep` / `localizeSnapshot(state, t)` at presentation time.
- Web snapshots include both localized `text`/`label` and optional `i18n: { key, params? }` so clients can re-localize history after `set_locale`.

## Package `@animae/i18n`

### React (`@animae/i18n/react`)

Browser-safe bindings (no Node-only imports). Peer dependency: `react`.

```tsx
import { createI18n } from "@animae/i18n/browser";
import { I18nProvider, useT, useLocale, loadCatalogs } from "@animae/i18n/react";

const catalogs = loadCatalogs(import.meta.glob("./locales/**/*.json", { eager: true }));
const i18n = createI18n({ locale: "en", catalogs });

export function App() {
  return (
    <I18nProvider i18n={i18n}>
      <Toolbar />
    </I18nProvider>
  );
}

function Toolbar() {
  const t = useT();
  const [locale, setLocale] = useLocale();
  return (
    <>
      <span>{t("web:chrome.title")}</span>
      <button type="button" onClick={() => setLocale(locale === "en" ? "zh-CN" : "en")}>
        {locale}
      </button>
    </>
  );
}
```

- `I18nProvider` accepts `i18n` or `translator` (`I18nInstance` from `createI18n`).
- `setLocale` calls `withLocale` and re-renders `useT` / `useLocale` subscribers.
- `loadCatalogs(modules)` merges eager glob maps keyed by `…/locales/<locale>/<namespace>.json`.

### Core API

```ts
import { createI18n, createTranslator, negotiateLocale, localizeError, localizeValue, localizeDeep } from "@animae/i18n";

const i18n = createI18n({
  locale: negotiateLocale({ env: process.env, explicit: "en" }),
  catalogs: { errors: { en: enErrors, "zh-CN": zhErrors } },
  defaultNamespace: "errors",
});

i18n.t("config.invalid");
i18n.t("errors:storage.path_escape", { path: ".." });

// Per-request (web):
import { runWithLocale } from "@animae/i18n";
runWithLocale(i18n.withLocale("de-DE"), () => handler());
```

- **Catalogs**: `packages/<pkg>/locales/<locale>/*.json` — nested keys, ICU subset (`{name}`, plural/select, `Intl` number/date/relative).
- **Prompts**: `engine/src/prompts/<locale>/sections.json` — same template ids in every locale; parity checked in tests / `animae i18n check`.
- **Fallback chain**: `buildFallbackChain(tag)` — tag → language variants → `en` (last-resort only; not privileged in product copy).
- **Pseudo locale**: `xx-pseudo` or `en-XA` for QA (`tPseudo` / `applyPseudoLocale`).
- **Structured messages**: `{ code, params, namespace? }` for non-UI layers; format at the edge with `formatStructuredMessage`.
- **Errors**: `AnimaeError` + `localizeError(err, i18n.t.bind(i18n))`; wire errors expose `code`, `params`, localized `message`.

## `animae.yaml`

```yaml
i18n:
  locale: en          # UI / display strings
  promptLocale: zh-CN # LLM scaffolding + default content locale
  outputLocale: en    # player-facing generation
  contentLocale: zh-CN # optional override for authored overlays
  fallbackLocale: en
```

CLI: `animae --lang zh-CN run`, TUI: `:lang zh-CN`.

## Locale layers

Same machinery as [mods](./mods.md), but under `locales/<locale>/` at the data root:

- Full file replace: `locales/en/world/locations/home.yaml`
- Patch: `locales/en/world/locations/home.patch.yaml`
- String tables: `locales/en/strings.yaml` with `$t: key` in authored YAML **display** fields (names, short descriptions, labels — not LLM prompt bodies)

Validate completeness: `animae validate [--locale <uiLocale>]` (applies **content locale** overlays like the engine; resolves display `$t:` keys against **UI locale** string tables and fails on missing keys). `--locale` overrides config/`--lang` for that check only. Locale overlay and mod layered storage must expose `locales/<tag>/*.strings.yaml` via `listFiles("locales/<tag>")` so validators see merged string tables.

Games should keep **structure-neutral base YAML** and put display text in locale layers or `$t:` tables.

## Record/replay

Recording keys include the **final prompt text**; changing `promptLocale` or `outputLocale` changes keys. Changing **UI locale** alone does not alter timeline events or save slots — only localized presentation changes. Recording headers should include locale fields (see timeline recording metadata).

## `@animae/host` and `@animae/web`

- Catalogs: `packages/host/locales/{en,zh-CN}/host.json`, `packages/web/locales/{en,zh-CN}/web.json`.
- `SessionHost` stores system lines and errors as catalog keys / `LocalizableValue`; `localizeSnapshot` runs per client locale on the wire.
- Web protocol: client `hello` optional `locale`; `hello_ok` returns negotiated `locale` + `locales[]`; server also sends `locale { locale }`; `set_locale` triggers `locale`, `result`, and a fresh localized `snapshot`. See `packages/web/docs/protocol.md`.

### Language-neutral engine messages

Engine timeline events that surface human-readable copy should include a **`systemMessage`** (`{ code, params?, namespace? }`) alongside any legacy `message` string. UIs localize with `formatSystemMessage(msg, t)` from `@animae/engine` (or `engine.setUiLocale` + engine error catalogs). Example: `config.warning` carries `systemMessage: { code: "config.warning", namespace: "diagnostics", params: { code } }`.

### Host command API

Game colon commands receive `HostCommandApi` with:

- `locale(): string` — viewer UI locale
- `t(key, params?)` — translate in the `host` namespace (and merged engine error catalogs)

Same surface as TUI `CommandApi` (`locale` / `t` optional on both for backward compatibility). Built-in host colon commands store **`description` as catalog keys** (`command.desc.*` in `host.json`), not English literals in TS.

## Games

Games may ship their own catalogs (see `games/<id>/src/i18n/`). Engine packages stay game-agnostic; game names never appear under `animae/`.

## Migration guide (games)

1. **Split lanes** — Keep structural YAML neutral (ids, refs, mechanics). Put **display** copy in `locales/<uiLocale>/strings.yaml` and reference with `$t:keys` on names, labels, descriptions, achievement titles. Put **LLM-facing** prose (persona `card.md` bodies, knowledge docs, template guidance) under `locales/<contentLocale>/` overlay paths mirroring the base tree (`characters/<id>/card.md`, `world/knowledge/*.md`, …). Default `contentLocale` follows `promptLocale`; set `i18n.contentLocale: en` when you ship an English LLM layer later.
2. **Runtime APIs** — Store timeline/panel/system payloads as `LocalizedMessage` (`{ key, params?, ns? }`) or lifted `{ i18n: { key, params? } }`. Resolve at the edge with `engine.display.resolve(value, { locale })`, `renderMessage(msg, t)`, or host/web `localizeSnapshot`. Plain strings remain valid for generated narration (already localized by the model).
3. **Per-viewer UI** — Web: `hello.locale`, `set_locale`, server `locale` ack, localized `snapshot`/`error`/`toast`. Controller `outputLocale` for each turn = that client’s UI locale (`submitInput(..., { outputLocale })` / `scene.turn({ outputLocale })`).
4. **Validate** — `animae validate --locale <uiLocale>` checks `$t` tables for the UI lane and content files under `locales/<contentLocale>/` when any `locales/` tree exists.

### Minimal example (lantern village)

Fixture tested in `packages/engine/test/i18n/locale-layers-fixture.test.ts`:

```yaml
# world/locations/village.yaml (neutral structure)
id: village
name: $t:loc.village.name
summary: $t:loc.village.summary
```

```yaml
# locales/en/strings.yaml (display lane — UI locale)
loc:
  village:
    name: Lantern Village
    summary: Paper lanterns line the alleys.
```

```yaml
# locales/zh-CN/world/locations/village.yaml (content lane — LLM overlays)
summary: |
  LLM-facing place brief (zh-CN content locale).
```

Engine load lifts `$t:` to `{ i18n: { key } }` for replay-safe state; `engine.display.resolve(location, { locale: "zh-CN" })` resolves display keys without mutating stored events.

Entity id resolution (`resolveEntityRef`) uses `authoredFieldPlain` so `$t:` / `{ i18n }` names do not break matching when the canonical id is supplied; localized name matching still requires resolved display strings at the UI edge.
