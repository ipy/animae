# Internationalization (i18n)

Animae separates **three locale settings** (all BCP-47 tags, configured independently):

| Setting | Config / API | Purpose |
|---|---|---|
| **UI locale** | `i18n.locale`, `createEngine({ i18n: { locale } })`, CLI `--lang`, env `ANIMAE_LOCALE` | Engine-owned UI/system text: errors, CLI/TUI chrome, doctor/validate messages, introspection labels |
| **Prompt locale** | `i18n.promptLocale` | Language of **static LLM prompt scaffolding** under `engine/src/prompts/<locale>/` (appraisal, render, safety, memory, etc.) |
| **Output locale** | `i18n.outputLocale` (defaults to UI locale) | Language the model must use for **player-facing** narration/dialogue; injected via catalog message + `Intl.DisplayNames` |

Authored game content uses **content locale** (`i18n.contentLocale`, default `outputLocale`) via locale overlay trees (see [Locale layers](#locale-layers)).

## Package `@animae/i18n`

```ts
import { createI18n, createTranslator, negotiateLocale, localizeError } from "@animae/i18n";

const i18n = createI18n({
  locale: negotiateLocale({ env: process.env, explicit: "en" }),
  catalogs: { errors: { en: enErrors, "zh-CN": zhErrors } },
  defaultNamespace: "errors",
});

i18n.t("config.invalid");
i18n.t("errors:storage.path_escape", { path: ".." });

// Per-request (web):
import { runWithLocale } from "@animae/i18n";
runWithLocale(i18n.withLocale("de-DE"), () => handler());
```

- **Catalogs**: `packages/<pkg>/locales/<locale>/*.json` — nested keys, ICU subset (`{name}`, plural/select, `Intl` number/date/relative).
- **Prompts**: `engine/src/prompts/<locale>/sections.json` — same template ids in every locale; parity checked in tests / `animae i18n check`.
- **Fallback chain**: `buildFallbackChain(tag)` — tag → language variants → `en` (last-resort only; not privileged in product copy).
- **Pseudo locale**: `xx-pseudo` or `en-XA` for QA (`tPseudo` / `applyPseudoLocale`).
- **Structured messages**: `{ code, params, namespace? }` for non-UI layers; format at the edge with `formatStructuredMessage`.
- **Errors**: `AnimaeError` + `localizeError(err, i18n.t.bind(i18n))`.

## `animae.yaml`

```yaml
i18n:
  locale: en          # UI
  promptLocale: zh-CN # LLM scaffolding locale (must exist under prompts/)
  outputLocale: en    # player-facing generation
  contentLocale: en   # authored overlays + string tables
  fallbackLocale: en
```

CLI: `animae --lang zh-CN run`, TUI: `:lang zh-CN`.

## Locale layers

Same machinery as [mods](./mods.md), but under `locales/<locale>/` at the data root:

- Full file replace: `locales/en/world/locations/home.yaml`
- Patch: `locales/en/world/locations/home.patch.yaml`
- String tables: `locales/en/strings.yaml` with `$t: key` in authored YAML display fields

Validate completeness: `animae validate --locale …` (reference locale via `--reference` when added).

Games should keep **structure-neutral base YAML** and put display text in locale layers or `$t:` tables.

## Tooling

| Command | Purpose |
|---|---|
| `animae i18n check` | Catalog symmetry, placeholder parity, CJK literals in TS, prompt id parity |
| `animae i18n pseudo [text]` | Preview pseudo-localization |
| `bun scripts/i18n-inventory.ts` | Advisory English sentence literals + strict CJK counts per package |

Repo tests: `test/hygiene/i18n-cjk.test.ts`, `test/hygiene/i18n-catalogs.test.ts`.

## Record/replay

Recording keys include the **final prompt text**; changing `promptLocale` or `outputLocale` changes keys. Recording headers should include locale fields (see timeline recording metadata).

## Migrating `@animae/web` and `@animae/host`

Do **not** hard-code UI copy in TS. Pattern:

1. Add `locales/<locale>/web.json` (or host.json) catalogs.
2. `createTranslator({ locale, catalogs, namespaces: ["web"] })`.
3. `localizeError(err, t)` for RPC/HTTP error bodies.
4. Use `runWithLocale` per session/request from `Accept-Language` or user preference.

Run `bun scripts/i18n-inventory.ts` and grep `@animae/web` / `@animae/host` `src` for remaining literals before migrating.

## Games

Games may ship their own catalogs (see `games/<id>/src/i18n/`). Engine packages stay game-agnostic; game names never appear under `animae/`.
